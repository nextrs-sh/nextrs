# NextRS v0.1.0-rc.3

**Prerelease.** The third release candidate of NextRS v0.1.0. It is
experimental software.

NextRS serves the output of an official Next.js `next build` from a single
Rust binary with embedded V8. It replaces `next start`, not `next build`.

## Overview

rc.3 is a developer-experience and correctness update to rc.2:

- **`nextrs doctor`**, a new command: it checks, without running anything,
  whether a Next.js application and its production build suit NextRS, and
  says what to change.
- **Preconditions on static files:** `If-Match` and `If-Unmodified-Since`
  are evaluated for `/_next/static` and `public/` files; a failed one is a
  `412`.

Everything else in `nextrs start` and `nextrs inspect` behaves as in rc.2:
the same request handling, JavaScript execution, options, help screens and
`inspect` output.

## Scope

| | |
|---|---|
| Platform | Linux x86_64, glibc 2.35 or later (unchanged) |
| Next.js | 16.4.6 (primary) and 16.4.5, React 19.3.1 (unchanged) |
| Other Next.js 16.x | Starts with a warning (untested) |
| Other Next.js majors | Refused at startup |
| JavaScript engine | Embedded V8; isolates configurable (`--isolates`) |

## What's new: `nextrs doctor`

```bash
npx nextrs doctor              # the current directory
npx nextrs doctor .            # a project directory (or its .next directory)
npx nextrs doctor . --json     # one JSON document on stdout, for CI
npx nextrs doctor . --strict   # warnings fail too
```

Run `next build` first. Doctor reads files only. It never runs
`next build`, JavaScript or a server, creates no file or directory, binds
no socket and makes no network request. Node.js is not needed to run it.

### What it checks

| Section | Checks |
|---|---|
| Environment | Platform, C library and glibc version, whether the path is a Next.js project, the installed Next.js against the version policy |
| Build | `.next` present and readable, the build's Next.js version (tested, untested, unsupported, security advisories), installed versus build version, `node_modules/next` when JavaScript runs, `nextrs start`'s own startup checks, stale adapter output, missing `.next/static` |
| Compatibility | App and Pages Router, dynamic SSR, Route Handlers, `generateStaticParams`, Server Actions, ISR, Cache Components and Partial Prerendering, custom cache handlers, proxy and edge middleware, `next.config` rules, image optimization, edge-runtime routes, interception routes, `i18n`, `instrumentation.ts` |
| Node.js APIs | Native addons, TCP clients (database, cache, mail and queue drivers) and process-spawning packages in Next's file traces of each server entry |
| Runtime configuration | The options you plan to pass to `nextrs start`, parsed with `start`'s own code: `--js-runtime`, the outbound network allowlist (external rewrites, remote images, `fetch`), the data and image cache directories, forwarded headers, `.env` files NextRS does not load, `--js-env` names, `NEXT_DEPLOYMENT_ID`, the Server Actions key and body limit |

Doctor reuses what `nextrs start` runs (the adapter's inspection, the
version policy, the startup checks, the flag parsers), so the two do not
disagree. Features are classified with the statuses of the capability
matrix: `supported`, `experimental`, `partial`, `unsupported`, and
`unknown` for what no suite covers. Experimental means it works on the
fixtures, not that it is verified for your application.

### Output and exit codes

- **Text** on a terminal, with colors off for pipes, `NO_COLOR` and
  `TERM=dumb`. **`--json`** prints one deterministic document (schema
  version 1): no timestamps, findings in a fixed order, machine paths
  replaced by `.`, `<workspace>` and `~`.
- Every finding has a stable code (`NEXTRS-DOC-...`), a severity (`error`,
  `warning`, `unknown`, `info`, `pass`), a suggestion where there is one,
  and a documentation link.
- **Exit codes:** `0` no confirmed blockers; `1` confirmed blockers (with
  `--strict`, warnings too; `unknown` never fails); `2` invalid arguments,
  or the check could not run.

**Exit code 0 does not mean the application works under NextRS.** It means
Doctor found nothing known not to work. Test the build with `nextrs start`
and compare its responses with `next start`.

### Untrusted projects

Doctor may be pointed at someone else's checkout, `.next` included:

- environment variable values are never reported: variables appear by
  name, and `.env` files are read only for their names;
- build metadata linked from outside `.next` (a `BUILD_ID` that is a
  symlink to a credentials file, say) is not read; the assessment is then
  reported as incomplete (`NEXTRS-DOC-108`);
- Doctor's own reads are limited to regular files inside the project, its
  `.next` and its monorepo root, with size limits;
- `nextrs start`'s startup checks run only when every stored response is a
  regular file inside `.next`, within a memory budget, and `public/` has
  no linked directories; otherwise they are reported as not run;
- control characters from the project are escaped in text output.

Reference: `engineering/doctor.md` in the repository.

## Preconditions on static files

`If-Match` and `If-Unmodified-Since` were not evaluated for static files in
rc.2. They now are, as RFC 9110 specifies, for GET and HEAD:

- evaluated before `If-None-Match`, `If-Modified-Since` and `Range`: a
  failed precondition is never a `304` or a `206`;
- a failure is a `412 Precondition Failed` (plain text, no
  `Cache-Control`). `next start` answers it with its `500` error page;
- `If-Match` uses the strong comparison. Static files have weak ETags
  (`W/"<size>-<mtime>"`, as with `next start`), so a listed entity tag never
  satisfies it, and only `If-Match: *` does. `next start` (and rc.2, which
  ignored the header) answer such a request with the file;
- `If-Unmodified-Since` accepts HTTP-dates only; other date formats are
  ignored.

Pages, route handlers and `/_next/image` are unchanged: as with
`next start`, their revalidation ignores both headers. Browsers do not send
these headers when loading pages and assets.

## Dependency update

- `url` 2.5.8 → 2.5.9, for [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592),
  a stack overflow in `Url::origin()` on nested `blob:` URLs. NextRS takes
  URL origins in request routing, the outbound network policy and the image
  optimizer.

## Known limitations of Doctor

- **It is static.** It cannot tell whether the application behaves as
  under `next start`, which Node.js built-ins the code calls, which hosts
  server code fetches from (only rewrite destinations are known), or how
  the application behaves under load.
- **Node.js API findings are warnings, not blockers.** A traced package may
  be loaded only on a path that never runs. Doctor always reports Node.js
  API usage as not fully analyzed.
- **Run it on Linux x86_64.** On other platforms the release binary does
  not load. A binary built from source elsewhere reports its platform as
  untested.
- **It checks the environment it runs in.** `--js-env` names are checked
  for presence where Doctor runs, so run it with the service's
  environment for that check to be meaningful.
- **`nextrs inspect` and `nextrs start` follow links in `.next`.** Doctor
  refuses build metadata linked from outside `.next`; `inspect` and
  `start` still read it, as in rc.2. Inspect only builds you trust.

## Known limitation: an undersized compression cache

This is unchanged from rc.2. With the default `--compression-cache` (32 MiB)
and typical builds, the gzip copies of `/_next/static` and the prerendered
pages fit, and memory stays flat. If the cache is smaller than the set of
responses clients request, almost every request evicts an entry and
compresses again, on the blocking thread pool. In that case the process's
resident memory grows well above that of a disabled cache, because the
allocator retains memory freed across many threads. In a 90-minute test it
reached about 870 MiB, against about 185 MiB with the cache off, and was
still rising slowly. The memory in use stayed flat and no request failed.

To check for this, compare `nextrs_compression_cache_evictions` with
`nextrs_compression_cache_misses`: if they rise together, the cache is
undersized. Raise `--compression-cache` above the gzip size of the build's
assets, or set it to `0`. `engineering/configuration.md` (Response
compression) explains how to size it.

## Installation

**npm.** Release candidates are published under the dist-tag `next`, not
`latest`: install this one by its exact version.

```bash
npm install -D @nextrs/cli@0.1.0-rc.3      # or: pnpm add -D @nextrs/cli@0.1.0-rc.3
npx next build                              # Node.js builds the application
npx nextrs doctor .
./node_modules/@nextrs/cli/bin/nextrs start . --js-runtime embedded-v8
```

Without adding a dependency: `npx --yes @nextrs/cli@0.1.0-rc.3 doctor .`.
Bare `npx nextrs` without the package installed looks for an unrelated npm
package called `nextrs`.

**GitHub release binary:**

```bash
V=0.1.0-rc.3
curl -LO https://github.com/nextrs-sh/nextrs/releases/download/v$V/nextrs-v$V-linux-x86_64.tar.gz
curl -LO https://github.com/nextrs-sh/nextrs/releases/download/v$V/nextrs-v$V-linux-x86_64.tar.gz.sha256
sha256sum -c nextrs-v$V-linux-x86_64.tar.gz.sha256
tar -xzf nextrs-v$V-linux-x86_64.tar.gz
sudo install -m 0755 nextrs-v$V-linux-x86_64/nextrs /usr/local/bin/nextrs
nextrs --version        # nextrs 0.1.0-rc.3
```

- **Node.js is still required to build** the application (`next build`).
- **Running needs no Node.js, Rust or Cargo.** This includes
  `nextrs doctor`.
- **In production,** start the binary directly, not through `npx` or
  `npm start`, so that SIGTERM reaches the server.

## Upgrading from rc.2

No configuration change is needed: `nextrs start` and its options are as
in rc.2. A client that sends `If-Match` with a static file's weak ETag now
gets `412` (see above).

## Release status

**Experimental.** It has not run in production. Doctor was tested on the
repository's fixtures and build snapshots, and on one real application
(Velasia Airways). Cloud certification of the v0.1.0 series is a separate
step.

## Verifying the download

```bash
sha256sum -c nextrs-v0.1.0-rc.3-linux-x86_64.tar.gz.sha256
```

`BUILD-INFO.json` in the archive records the source commit, the compiler
(rustc 1.98.0), the Cargo profile (`dist`) and the binary's SHA-256.
